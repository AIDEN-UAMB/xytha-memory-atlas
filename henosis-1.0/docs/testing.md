# 测试与发行范围

`npm test` 顺序执行十组原版离线回归及 CLI 测试：

1. 任务规划：语义提案、原文、区间、补查范围。
2. 证据收集：确定性盘面、历史环境与候选覆盖。
3. 生成：模型协议、输出预算与恢复路径。
4. 运行时：容量压力、分区、网络中断和检查点重用。
5. 任务编排：相关任务组合、调查与交付结构。
6. 可靠性：异常、重试和有限恢复。
7. 效率：结构编码、候选保留与定向修复。
8. 路由：可选影子路由的隔离与无副作用。
9. 深度回答：分层草稿、依据、检查与呈现。
10. 时间回归：前史、候选区间与年度精度。

CLI 另测无密钥排盘、错误脱敏和原版指纹稳定性。用例只使用示例人物和受控响应；模型请求由测试拦截。测试不读取真实对话、不调用收费模型。

独立包唯一调整的原版测试是证据套件的保护文件列表：保留 `chart.ts`、`timing.ts`、`transformations.ts` 的哈希保护，删除本包不包含的 Nous 提示词与知识契约路径。没有删改业务断言来取得通过。

`npm run check` 校对来源哈希与阻止发布的路径、密钥模式。模式扫描不是完整安全审计。`ACCEPTANCE.json` 记录本次本地验收范围；GitHub Actions 另在 Windows 和 Linux 执行。

测试通过只代表这些工程行为通过，不证明所有服务商兼容、所有输入无错、专业判断正确，或优于 Henosis-2.0 / Nous。真实模型质量和专业案例需单独评测。
